# 玉米全基因功能字典知识图谱｜新成员入门说明

> **阅读对象**：新加入项目、目前没有编程或生物信息学基础的同学  
> **项目定位**：以玉米参考基因组为基础，建立可检索、可追溯、有自然语言对话能力的基因功能知识图谱网站。  
> **当前状态**：已经收集好文献和基因数据，正在进行数据清洗与分级

## 一、我们到底在做什么？

玉米有数万个基因，但这些基因的功能、关联性状和实验依据分散在基因组数据库、功能注释库以及科研论文中。

我们希望把它们整理成一个“**玉米全基因功能字典**”：用户既能像查字典一样搜索基因，也能像与科研助手交流一样，用自然语言提出问题，获得**附带证据来源、说明不确定性**的回答。

项目题目暂定为**《玉米全基因功能字典知识图谱》**。

**“全基因”指系统尽量覆盖所选玉米参考基因组中的全部目标基因，不意味着所有基因的功能都已知或已经得到实验验证。** 对证据不足的基因，系统必须明确标注“未知”“缺少直接证据”或“计算推断”。

## 二、网站必须有哪些功能？

### 1. 搜索框：精确查询

网站首页需要有一个**醒目的搜索框**，支持输入：

- 玉米基因 ID（如 B73 v5 格式的 `Zm00001eb...`）、基因名称或别名；
- 功能关键词，例如“转录因子”“蛋白激酶”；
- 性状名称，例如“开花时间”“抗旱性”“籽粒发育”。

搜索结果应展示相关基因列表；点击某个基因后，进入**基因详情页**，查看基本信息、功能注释、相关性状、证据类型和来源链接。

**搜索框的定位是快速检索和浏览已有结构化信息**，不应把搜索结果直接称为预测结果。

### 2. 对话入口：大语言模型科研问答

网站还必须提供一个与搜索框明显区分的**“AI 科研助手 / 开始对话”入口**。点击后进入聊天界面，用户可以连续追问，例如：

- “这个玉米基因可能有哪些功能？有哪些实验支持？”
- “这个基因与开花时间有关吗？证据强不强？”
- “有哪些可能与抗旱性相关、但尚缺乏直接功能验证的候选基因？”
- “为什么把这些基因排在前面？请列出依据。”

**大语言模型（LLM）不是我们知识的唯一来源。** 理想的回答流程是：

`用户提问 → 识别基因/性状 → 检索知识图谱和文献证据 → 组织检索结果 → LLM生成中文解释 → 展示引用、证据类型及不确定性`

这种“先检索可信信息、再生成回答”的方式可采用 **GraphRAG（知识图谱增强检索生成）**。首先做可靠的检索与证据展示，再逐步接入大模型；不能让模型凭自身记忆编造基因作用或实验结论。

**对话页至少应该有：** 消息输入框、发送按钮、历史消息区域、回答引用/证据卡片、相关基因跳转，以及“证据不足”的提示。多轮对话可以作为后续增强目标。

### 3. 性状候选基因排序

用户输入一个性状，系统根据已有功能注释、遗传关联、同源关系等信息，对参考基因组范围内的基因进行候选排序，并解释每个基因的得分依据。

**候选排序不等于实验验证。** 必须区分已知相关基因与尚未验证的预测候选，并设计独立评估，检查排序是否优于简单基线。

## 三、什么是知识图谱？

知识图谱不是一张普通图片，而是一种把信息连接起来的数据结构。

例子：

```text
基因A ──编码──> 蛋白B
基因A ──具有注释──> 功能C
基因A ──与性状相关──> 性状D
论文E ──支持/报道──> 上述关系
```

- **实体（节点）**：基因、蛋白、功能、性状、论文等。
- **关系（连接）**：编码、注释、关联、支持、同源等。
- **证据**：关系来自哪个数据库或哪篇论文、采用什么实验方法、可以得出多强的结论。

项目可使用 **Neo4j** 存储知识图谱；通过网页后端接口读取图谱，再呈现在网站和聊天界面上。

## 四、已有数据与我们要重新做的工作

我们已经下载了**原始数据**，例如玉米基因注释、GO功能注释、蛋白结构域、同源基因数据和文献记录。现有文献检索集合约有22.5万条记录，并已进行过初筛保留7.8万条；**不代表每篇都能提供玉米基因功能证据**。

已有数据仍须核对版本、文件完整性、基因ID匹配和证据来源。

大致的数据流程：

`原始数据 → 字段清洗和基因ID统一 → 文献及结构化证据整理 → 功能预测排序模型构建 → 图谱构建 → 搜索接口/问答检索 → 网站展示与实验验证`


## 五、文献为什么要分 A、B、C、D 等类别？

不同研究能够支持的结论强度不同。团队沿用此前确定的文献主标签体系：

| 标签 | 基本含义 | 需要注意 |
|---|---|---|
| **A** | 基因或蛋白的直接功能实验 | 要核对实验研究的是不是玉米基因、实验对象和结果是什么 |
| **B** | 具体基因/等位基因与性状关系 | 必须能追溯到具体遗传对象与表型关系 |
| **C** | GWAS、QTL、表达、组学等关联研究 | **关联不等于因果** |
| **D** | 同源、序列分析及计算推断 | 推断不能当作直接实验证实 |
| **E** | 数据库、基因组或功能资源 | 主要提供数据和方法来源 |
| **R** | 综述或研究进展 | 优先追溯其引用的原始研究 |
| **X** | 不符合当前核心研究范围 | 不一定等于“完全没有提到玉米” |
| **U** | 信息不足，暂不能可靠判断 | 不应强行归类或永久删除 |

自动分类只是**候选标签**；正式进入知识图谱的功能关系还需要保留证据原文、来源和验证状态。同一篇论文可能包含不止一种证据。

## 六、项目完成后，应当能展示什么？

按目前提出的目标，论文计划至少包含四张核心大图：

1. **网站与系统展示**：搜索框、基因页面、AI对话入口和整体使用流程。
2. **数据类型与知识图谱结构**：基因覆盖、功能注释、证据来源、节点关系等。
3. **基因功能查询示例**：输入基因，输出有文献或数据库来源支持的功能解释/遗传机制线索。
4. **性状未知候选基因排序**：输入性状，显示全基因组候选排序、依据与验证结果。

注意：论文要证明系统在**覆盖、证据可靠性和候选排序有效性**方面的贡献，不能只靠网页截图证明科研创新。

**一句话总结：我们要自己做一个有搜索框、AI对话入口和可追溯证据的玉米全基因功能知识网站，并通过科学实验说明它为什么可信、有什么研究价值。**
